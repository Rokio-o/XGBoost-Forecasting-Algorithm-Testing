# AerIntel Forecasting Algorithm Testing

## Overview

This project is a development and algorithm-testing pipeline for **1-hour-ahead CO2 forecasting** using the AerIntel synthetic sensor dataset.

The workflow prepares historical sensor data through feature engineering, then trains and evaluates seven forecasting/regression algorithms:

1. ARIMA
2. Random Forest
3. Support Vector Regression (SVR)
4. XGBoost
5. LightGBM
6. Multi-Layer Perceptron (MLP)
7. Long Short-Term Memory (LSTM)

The purpose of this project is to compare the forecasting performance of different algorithms before applying the pipeline to the actual AerIntel historical sensor data.

> **Important:** The current results are based on synthetic data and should be treated as development/testing results, not as the final thesis results.

# Step 1 — Feature Engineering

The first script is:

```text
feature_engineering.py
```

Its purpose is to prepare the raw synthetic sensor data for 1-hour-ahead CO2 forecasting.

## Processing Flow

```text
Raw Synthetic Dataset
        ↓
Select N01 Sensor Node
        ↓
Sort Observations Chronologically
        ↓
Set Timestamp as Index
        ↓
Create Time Features
        ↓
Create Lag Features
        ↓
Create Rolling Features
        ↓
Add Supporting Sensor Features
        ↓
Create Next-Hour Target
        ↓
Remove Rows With Missing Values
        ↓
Save Processed Dataset
```

## Features Created

### Time Features

- `hour`
- `dayofweek`
- `is_weekend`

### Historical CO2 Features

- `co2_lag1`
- `co2_lag2`
- `co2_lag3`
- `co2_lag24`

These represent previous CO2 observations at different time lags.

### Rolling Features

- `co2_roll3`
- `co2_roll6`

These represent shifted rolling averages over the previous 3 and 6 hours.

### Supporting Sensor Features

- `temperature_c`
- `humidity_pct`
- `occupancy_count`

### Target Variables

- `target` — CO2 value at the current timestamp
- `y` — CO2 value at the next hour

The forecasting objective is therefore:

```text
Current and historical information
              ↓
       Predict next hour CO2
```

# Train/Test Split

The dataset is divided chronologically rather than randomly.

Current synthetic-data experiment:

```text
Training observations: 2426
Testing observations:   429
```

Test period:

```text
2025-09-12 02:00:00
to
2025-09-29 22:00:00
```

Chronological splitting is used because the task is time-series forecasting. The model should be trained using earlier observations and evaluated on later observations.

---

# Evaluation Metrics

The models are evaluated using:

- MAE
- MSE
- RMSE
- MAPE
- R²

## MAE

Mean Absolute Error.

Lower values indicate smaller average prediction errors.

## MSE

Mean Squared Error.

Lower values indicate smaller prediction errors, with larger errors receiving greater penalties.

## RMSE

Root Mean Squared Error.

Lower values indicate better predictive performance.

## MAPE

Mean Absolute Percentage Error.

Lower percentages indicate smaller relative prediction errors.

## R²

Coefficient of Determination.

Higher values indicate that the model explains more of the variation in the target values.

However, these results are only preliminary because they were obtained using the synthetic dataset.
